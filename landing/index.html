CHALLENGE

AI 時代に急速に積み上がる「理解負債」

Claude Code・Codex・Gemini CLI などの普及で「開発」と「運用」のサイクルは加速する一方、その速さの中でコードを「理解する」ことが後回しにされ、AI が生成したコードが何をしているか・なぜそう書かれているかを説明できない「理解負債」が急速に蓄積しています。

「動けばよい」で理解が置き去り

納期とデプロイ速度が優先され、コードを理解するステップが省かれる。書いた人以外は中身が分からないまま進む。

AI 任せで思考がスキップされる

もっともらしい生成コードをそのまま信頼し、「なぜそう書くのか」を問わないまま本番へ。理解されないコードが増え続ける。

「理解しているか」は測られない

レビューやテストは品質を測っても、人の理解度は測らない。どこから手を付けるべきか、緊急度も分からない。

理解度とコード品質を、可視化して改善する

理解度

  • 可視化｜理解度マップ — 誰がどこを理解しているかをファイル単位のグラフで俯瞰。
  • 改善｜クイズと学習 — クイズで実測し、学習プランで埋める。合格で理解度↑。

コード品質

  • 可視化｜コード品質マップ — ファイル単位で品質の低いコードの分布を俯瞰。
  • 改善｜コード改善 — AI に頼む（修正 PR）／人に頼む（Issue）で対応。

実測 → 改善の閉ループ

検知は出発点ではなく「どの理解ギャップが緊急か」を示すホットスポット信号。主役は理解度の実測と向上です。

  1. 01

    解析する

    検知・理解度・機能クラスタリングをまとめて実行。

  2. 02

    クイズで実測

    git blame に頼らず、理解度を能動的に計測する。

  3. 03

    学習で深める

    チーム資産を優先した学習プランで理解度を引き上げる。

  4. 04

    修正 PR

    AI が改善案を生成し、GitHub に修正 PR を作成する。

CORE

3 つのコア機能

01

AI エージェントによる高度なリポジトリ解析

Google ADK で構築したエージェントが MCP（Serena / CodeGraphContext / Semgrep / GitHub）を駆使してリポジトリを探索。機能ごとの学習プラン・クイズの生成、低品質コードの検知と修正計画の作成までを自動化します。

02

理解負債の可視化 × クイズと学習で改善

ソースコードを機能単位にクラスタリングし、機能ごとに学習プランと理解度確認テストを生成。グラフで理解負債を可視化し、クイズ → 学習の閉ループで能動的に返済します。

03

低品質コードへの推奨提案と自動修正

解析で検出した低品質コードに対し、推奨事項を GitHub Issue として起票。担当者の割り当てや、修正 PR の自動作成まで行えます。

Understanding Map

理解度マップ — 誰がどこを分かっているか

機能・ファイル別に、ユーザーの理解度をグラフで可視化します。表示はマップとリストの 2 種類。機能チップで特定機能に関わるファイル群だけに絞り込めます。マップ表示はノード＝ファイル、線＝依存関係、色＝理解度で、ノードを選ぶと隣接ファイルを強調表示。

  • 理解済み
  • 部分理解
  • 未理解
  • 未着手
CodeGraphContext によるグラフ可視化 ファイル間の依存関係解析 機能クラスタリング

コード品質マップ — 品質の分布を俯瞰

ソースコードをファイル単位で閲覧し、どのファイルにどのような改善余地があるかを確認できます。

  • ・左のファイルツリーからファイルを選択。改善余地があるファイルにはバッジが付きます。
  • ・右側に選んだファイルの中身を表示。指摘箇所がハイライトされ、その場で確認できます。

Quizzes & Learning

クイズと学習 — 実測して理解を深める

機能ごとの学習プランを受講し、確認クイズで理解度をチェックします。

  • ・学習プラン一覧 — 各プランのステータスと理解度、全体の学習進捗を確認。復習したい単元にはフラグを付け、一覧上部にまとめられます。
  • ・学習を開く — リポジトリ特有の機能をウォークスルーで学び、関連技術の公式ドキュメントも参照。重要な処理を段階的に理解。
  • ・理解度を確認する — 確認クイズを受験。あとで復習したい問題にフラグを付けられ、フラグ／誤答に絞った再テストで弱点を繰り返し復習できます。
ADK エージェントが学習プラン・クイズを生成 リポジトリ特有 × 技術スタックの両輪で学習 フラグ付け・誤答の再テスト

Code Improvement

コード改善 — PR / Issue で返す

ファイル単位で改善箇所を確認し、AI による修正 Pull Request の自動生成や Issue の作成が行えます。

  • ・フィルタで絞り込み、優先度順に並び替え。改善対象をクリックで詳細画面へ。
  • ・詳細画面では問題のコード箇所がハイライトされ、品質が低い理由・優先度・推定工数を確認。
  • ・改善方法は「AI に修正 PR を自動作成」か「担当者を割り当てて Issue を作成」から選択。

INFRASTRUCTURE

インフラ構成

Google Cloud 上のコンテナ構成。重い解析は非同期ワーカーへ分離し、負荷に応じて Cloud Run が自動スケールします。解析は ADK で構築したエージェントと MCP の活用により、網羅的かつ効率的なリポジトリ探索を実現。
Cloud Armor によるレート制限・Secret Manager および Workload Identity でセキュリティを担保し、インフラは Terraform で IaC 化しています。
開発時には、CI/CD がテスト〜デプロイに加えてリンター／フォーマッターの自動適用と Gemini による自動コードレビューまで回して、コード品質を高く保ちます。

アプリ実行 — Cloud Run

api（外部公開・SPA 同梱）と service（内部・重い解析の Cloud Tasks ターゲット）を分離。

データ — Cloud SQL

PostgreSQL ＋ pgvector。Alembic でスキーマ管理。

非同期ジョブ — Cloud Tasks

検知・理解度・クラスタリング等の重処理をワーカーへ委譲。冪等・再配送前提の設計。

公開・防御 — LB / Cloud Armor

外部 HTTPS ロードバランサ＋マネージド証明書。レート制限はエッジで強制。

機密・レジストリ

Secret Manager（平文環境変数は不可）／Artifact Registry でコンテナ管理。

IaC — Terraform

全リソースをコード化。デプロイは Workload Identity Federation（長期鍵レス）で GitHub Actions から実行。

CI/CD — 品質の自動化

GitHub Actions でテスト・デプロイを自動化。Ruff／Prettier／ESLint の自動適用、Gitleaks・CodeQL・OWASP ZAP スキャン、そして Gemini による自動コードレビューでコード品質を担保。

SECURITY

セキュリティでこだわっていること

認証・セッション

アクセス JWT（5 分）とリフレッシュ（7 日・DB 管理）の Cookie を分離。ローテーション＋再利用検出、`token_epoch` による即時ログアウト無効化。

CSRF / オリジン

SameSite=Lax ＋ Origin 検証ミドルウェア、トークンに固有 audience を付与して用途を分離。

鍵を持たない設計

Workload Identity Federation で長期クレデンシャルを排除。秘密は Secret Manager に集約（平文環境変数なし）。

ジョブ分離（方式 B）

キューには秘密を載せず、ワーカーが実行時に Secret Manager から GitHub トークンを mint。キュー無効時はフェイルクローズ。

エッジでのレート制限

Cloud Armor によりアプリ手前で制限。アプリ内のレート制御に依存しません。

LLM の安全策

リポジトリ内容は「データ（指示ではない）」として境界を明示。生成物を検証（空・巨大な改変を拒否）し、PR は未レビュー明示。

エージェント入力のマスキング

エージェント（LLM）に情報を与える際は、Cloud DLP（Sensitive Data Protection）と detect-secrets で PII・シークレットをマスキングしてから送信します。

脆弱性スキャン（OWASP 準拠）

OWASP に準拠した脆弱性スキャンを実施済み。認証・入力・依存関係など主要なリスク観点を点検しています。
