CHALLENGE

AI 時代に急速に積み上がる「理解負債」

Claude Code・Codex・Gemini CLI などの普及で「開発」と「運用」のサイクルは加速する一方、その速さの中でコードを「理解する」ことが後回しにされ、AI が生成したコードが何をしているか・なぜそう書かれているかを説明できない「理解負債」が急速に蓄積しています。

「動けばよい」で理解が置き去り

納期とデプロイ速度が優先され、コードを理解するステップが省かれる。書いた人以外は中身が分からないまま進む。

AI 任せで思考がスキップされる

もっともらしい生成コードをそのまま信頼し、「なぜそう書くのか」を問わないまま本番へ。理解されないコードが増え続ける。

「理解しているか」は測られない

レビューやテストは品質を測っても、人の理解度は測らない。どこから手を付けるべきか、緊急度も分からない。

オンボーディング担当 / 新規参画メンバー

どこから理解すべきかを、学習ユニットとクイズで体系的に追いたい。

HOW IT WORKS

開発・運用のサイクルに、技術負債・理解負債の解消を取り込む

解析から、理解の実測・品質の検知、学習・改善までを一気通貫。「実測 → 学習」と「検知 → 改善」の両輪で返済します。

リポジトリ解析
AI エージェントが MCP を使ってコードベースを横断探索。ファイル群を機能単位にクラスタリングし、技術スタックや依存関係も把握。
理解負債
クイズを生成・実測
機能ごとに理解度クイズを自動生成。回答から「誰がどこを理解しているか」をファイル単位で客観的に実測。
学習プランを生成
理解が浅い機能に合わせ、該当コードのウォークスルーや技術ドキュメントを含む学習プランをエージェントが自動で組み立て。
技術負債
低品質コードの検知
重複・複雑度・デッドコード・AI 生成痕跡などを解析し、品質が低く優先度の高いファイルを特定。
コード改善を提案
低品質コードに対し AI が自動で修正 PR を作成。担当者を割り当てた Issue の起票にも対応。
理解度・品質が向上
「実測 → 学習」と「検知 → 改善」の両輪で属人化を解消し、コードベースの理解度とコード品質を継続的に向上。

CORE

3 つのコア機能

AI エージェントによる高度なリポジトリ解析

Google ADK で構築したエージェントが MCP（Serena / CodeGraphContext / Semgrep / GitHub）を駆使してリポジトリを探索。機能ごとの学習プラン・クイズの生成、低品質コードの検知と修正計画の作成までを自動化します。

理解負債の可視化 × クイズと学習で改善

ソースコードを機能単位にクラスタリングし、機能ごとに学習プランと理解度確認テストを生成。グラフで理解負債を可視化し、クイズ → 学習の閉ループで能動的に返済します。

低品質コードへの推奨提案と自動修正

解析で検出した低品質コードに対し、推奨事項を GitHub Issue として起票。担当者の割り当てや、修正 PR の自動作成まで行えます。

Understanding Map

理解度マップ — 誰がどこを分かっているか

機能・ファイル別に、ユーザーの理解度をグラフで可視化します。表示はマップとリストの 2 種類。機能チップで特定機能に関わるファイル群だけに絞り込めます。マップ表示はノード＝ファイル、線＝依存関係、色＝理解度で、ノードを選ぶと隣接ファイルを強調表示。

  • 理解済み
  • 部分理解
  • 未理解
  • 未着手
CodeGraphContext によるグラフ可視化 ファイル間の依存関係解析 機能クラスタリング

Code Quality Map

コード品質マップ — 品質の分布を俯瞰

  • ・左のファイルツリーからファイルを選択。改善余地があるファイルにはバッジが付きます。
  • ・右側に選んだファイルの中身を表示。指摘箇所がハイライトされ、その場で確認できます。

Quizzes & Learning

クイズと学習 — 実測して理解を深める

機能ごとの学習プランを受講し、確認クイズで理解度をチェックします。

  • ・学習プラン一覧 — 各プランのステータスと理解度、全体の学習進捗を確認。復習したい単元にはフラグを付け、一覧上部にまとめられます。
  • ・学習を開く — リポジトリ特有の機能をウォークスルーで学び、関連技術の公式ドキュメントも参照。重要な処理を段階的に理解。
  • ・理解度を確認する — 確認クイズを受験。あとで復習したい問題にフラグを付けられ、フラグ／誤答に絞った再テストで弱点を繰り返し復習できます。
ADK エージェントが学習プラン・クイズを生成 リポジトリ特有 × 技術スタックの両輪で学習 フラグ付け・誤答の再テスト

SECURITY

セキュリティでこだわっていること

認証・セッション

JWT トークンを用いた GitHub SSO。アクセストークンとリフレッシュトークンを用いた安全なセッション管理。30 分間操作がないときのセッションタイムアウト。

同一オリジン配信と Web 脆弱性対策

UIとAPIを同一オリジンで配信することでCORS 設定不要。加えて、XSS・CSRF・SSRF等の Web アプリで必要な対策を実施。

鍵を持たない設計

Workload Identity Federation で長期クレデンシャルを排除。デプロイ時のシークレットは GitHub Secrets で注入し、実行時は Secret Manager に集約して管理します。

エッジおよびアプリ内でのレート制限

Cloud Armor によりアプリ手前で過剰なリクエストを制限。アプリ内では管理者がリポジトリ解析のクレジットを付与・管理でき、コストの大きい解析処理の乱用を防ぎます。

エージェント入力のマスキング

エージェントに情報を与える際は、Cloud DLP（Sensitive Data Protection）と detect-secrets で PII・シークレットをマスキングしてから送信します。

脆弱性スキャン

OWASP に準拠したアプリケーションの脆弱性スキャンおよび、Trivy を用いたコンテナイメージの脆弱性スキャンを実施。
